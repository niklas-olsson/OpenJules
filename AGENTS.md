# Contributor guidance

Use the [README source and documentation map](README.md#source-and-documentation-map)
to find the implementation and its existing explanation.

Update that explanation when behavior, commands, configuration, recovery,
guarantees or evidence change. Update the map when routing changes. Internal
refactoring needs no cosmetic documentation change or routine declaration.

Keep authorization, execution, capture, publication and acceptance distinct.
Preserve host-owned credentials and identities, original operation keys,
retained uncertainty and source authorship. Independent public peers may decline
or leave; a discussion message is not execution permission.

Distinguish intended behavior, implemented behavior, component tests and installed
demonstrations. Tie qualification claims to exact revisions and recorded
validation; retain unresolved findings. Polyphony owns canonical task authority;
OpenJules owns its runtime and capture boundaries; ZPM owns installed pins and
joined acceptance.
